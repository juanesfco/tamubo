# AutoIA validated elementary functions

**Checkpoint:** `0.14.0.dev1`  
**Status:** Validated real elementary-function layer, extended in `1.0.4.dev6` with `tanh`, `sinh`, `arctan`, `abs`, `log1p`, and `cosh`.

## 1. Scope

AutoIA now recognizes the ordinary one-argument forms

```python
np.sqrt(x)
np.exp(x)
np.log(x)
np.log1p(x)
np.sin(x)
np.cos(x)
np.sinh(x)
np.cosh(x)
np.tanh(x)
np.arctan(x)
np.abs(x)
```

and the analogous standard-library `math` calls when those module/global bindings
are visible to AutoIA's local shadow-namespace dispatcher.  Module-level direct
aliases such as `from numpy import sin` and `from math import cos` are also
recognized.

The implementation does not assume the platform transcendental library is
correctly rounded.  Platform `sqrt` or `pi` values may be used as *proposals* for
an endpoint or an argument-reduction integer, but accepted proof bounds are
constructed from the audited trusted binary64 `+`, `-`, `*`, `/` kernel and
analytic remainder inequalities.

## 2. Trusted scalar kernels

### 2.1 Square root

For one exact binary64 point `x >= 0`, a platform square root is used only as a
candidate `y`.  AutoIA accepts a lower candidate `L` only after trusted interval
squaring proves

    L^2 <= x,

and accepts an upper candidate `U` only after trusted squaring proves

    U^2 >= x.

Inputs near either end of the finite binary64 exponent range may be scaled by an
even power of two before the endpoint proof. For subnormal inputs this prevents
the proof square from underflowing too severely. As of `0.22.0.dev2`, inputs near
the largest finite value are likewise scaled so that a one-ulp adjustment of an
upper root proposal cannot make the proof square overflow. The exact-real
identity `sqrt(x) = 2^s sqrt(x / 2^(2s))` is implemented entirely with trusted
interval operations; the platform square root remains only a proposal. The
interval extension uses monotonicity.

### 2.2 Exponential

For a point `x`, AutoIA repeatedly halves the rigorous point enclosure until the
reduced interval `r` satisfies `|r| <= 1/8`.  It evaluates the Taylor polynomial

    exp(r) = sum_{k=0}^N r^k/k! + R_N

with trusted interval arithmetic.  If `a >= |r|`, then

    |R_N| <= exp(a) a^(N+1)/(N+1)!
             <= a^(N+1) / ((N+1)! (1-a)),

because `exp(a) <= 1/(1-a)` for `0 <= a < 1`.  Repeated trusted squaring then
recovers `exp(x)`.  Positivity is intersected in after underflow widening.

Finite proof-critical overflow remains fail-closed under the reference backend.

### 2.3 Natural logarithm

For positive binary64 `x`, AutoIA extracts `k = floor(log2(x))` directly from the
binary64 bit pattern and writes

    x = 2^k m,

with `m` rigorously enclosed near `[1,2)`.  It then uses

    log(m) = 2 atanh(z),
    z = (m-1)/(m+1),

and the absolutely convergent odd-power series

    atanh(z) = sum_{j=0}^infinity z^(2j+1)/(2j+1).

If `a >= |z| < 1`, the omitted tail after the retained terms is bounded by

    a^(2N+3) / ((2N+3)(1-a^2)).

A rigorous `ln(2)` interval is generated by the same formula with `z = 1/3`, so
no trusted platform `log` constant is needed.

### 2.4 Sine and cosine

A rigorous `pi` interval is generated from Machin's identity

    pi = 16 atan(1/5) - 4 atan(1/239),

with rigorously bounded alternating arctangent series.

For an argument interval `X`, an ordinary floating-point estimate chooses one
integer `n`.  That choice is not trusted.  AutoIA rigorously constructs

    R = X - n*pi/2,

so the exact identity remains valid for whichever integer was chosen.  If the
reduced interval is small enough, sine and cosine are evaluated by Taylor series
with the global derivative bound `|f^(j)| <= 1`.  If argument reduction is too
wide, AutoIA returns the sound fallback `[-1,1]`.

Thus very large trigonometric arguments may be certified coarsely rather than
relying on an unproved high-precision argument reducer.

## 3. Generic polynomial lifting

Let `x(q)` be the actual scalar program quantity represented by a polynomial
AutoIA value, and let a rigorous interval `X` contain every possible `x(q)`.
Choose a stored binary64 center `c in X` and define

    delta(q) = x(q) - c.

For polynomial order `K`, AutoIA uses

    f(x) = sum_{n=0}^K a_n delta^n + remainder,

where

    a_n = f^(n)(c)/n!.

The important detail is that `a_n` is **not assumed to be known exactly**.  A
trusted scalar kernel returns an interval `A_n` containing the exact coefficient.
AutoIA chooses an ordinary binary64 representative `ahat_n in A_n` and stores

    A_n = ahat_n + E_n,

where `E_n` is a rigorous interval coefficient error.  The existing generic
polynomial-plus-remainder arithmetic then propagates `E_n`, the input remainder,
and polynomial truncation.  A separate analytic Taylor remainder is added at the
end.

This is one reusable composition mechanism for the supported smooth functions rather than
separate polynomial-algebra implementations for each function.

## 4. Remainder bounds used by the polynomial lift

For `exp`, the Lagrange derivative maximum is obtained from the trusted monotone
`exp(X)` enclosure.

For `sin` and `cos`, every real derivative has magnitude at most one.

For `log`, the implementation exploits the convergent local series

    log(c+delta) = log(c) + log(1+u),
    u = delta/c,

and, for `|u| <= a < 1`, bounds the degree-`K` tail with

    a^(K+1) / ((K+1)(1-a)).

For `log10`, AutoIA uses the exact-real identity `log10(x) = ln(x)/ln(10)`.
The trusted kernel rigorously encloses both the natural-log numerator and the
positive constant `ln(10)`, and interval division is outward-rounded.  The
polynomial Taylor coefficients and remainder bound are scaled by that same
rigorous `ln(10)` interval rather than by an ordinary floating-point reciprocal.

For `sqrt`, the local binomial series

    sqrt(c+delta) = sqrt(c) (1+u)^(1/2)

is used.  Since the magnitude ratio of successive omitted binomial terms is less
than `a = |u|`, the tail is bounded by the first omitted term divided by `1-a`.
A conservative Lagrange fallback remains available if the local series condition
cannot be proved.

## 5. Domain rules

`log` and `log10` require the argument to be **strictly positive** on the entire physical
input box.  `sqrt` requires it to be **nonnegative**.

As of `0.22.0.dev1`, these conditions are proved by the general physical-domain
predicate mechanism rather than by trusting a single representation range.  Let
`P` denote the original physical input box, let `p_c` be the stored center, and
let

    Q_phys = {p - p_c : p in P}

be the actual centered physical set.  The polynomial layer may use a larger
symmetric proof box `Q`, with `Q_phys` contained in `Q`.  A validated scalar may
also carry an independent natural interval `N_z` enclosing its value on
`Q_phys`.  The domain prover intersects independently rigorous candidates such
as `N_z`, termwise, monotonicity, and bounded-cost Bernstein ranges.

Consequently, `sqrt(x)` on the physical interval `[0,4]` certifies even if the
symmetric centered polynomial range extends a few ulps below zero.  AutoIA does
**not** replace that negative structural endpoint by zero.  It proves the
physical-domain predicate from an independent enclosure valid on `Q_phys`.

If the whole-box predicate is unresolved, path-aware execution may geometrically
subdivide the physical box and retry.  All children must prove the requirement;
otherwise AutoIA fails closed.  If a proven square-root range touches zero, the
current implementation may deliberately use a dependency-destroying interval
lift because the local Taylor expansion about a positive center is not uniformly
regular through the boundary.

## 6. Current dispatch boundary

The local dispatcher supports module/global NumPy and `math` bindings and their
direct aliases.  A local `import numpy` or `import math` executed inside the model
body is not rewritten by the current shadow-global mechanism.  Helpers imported
from other modules are also not recursively rewritten.  Unsupported forms fail
closed.

## 7. Validation

The regression suite checks the elementary-function family under both polynomial and interval
representations, nonlinear multivariate arguments, object-array use, composition,
and postprocessing after semantic operations. The `1.0.4.dev6` additions have a
separate dense-grid and high-precision audit in `tests/test_added_elementary_functions.py`.

`tests/test_trusted_elementary.py` compares the trusted scalar kernels against an
independent high-precision `mpmath` oracle.  The standalone tool
`tools/audit_elementary.py` is configurable for larger stress sweeps and is not
part of the installed package.


## Constant real powers

The companion `0.14.0.dev2` power extension reuses this elementary-function
layer rather than adding a separate transcendental proof system.  For a
non-integer constant exponent `p` and positive validated base `x`, AutoIA
decomposes `p=n+r` with integer `n` and small exact binary64 residual `r`, then
uses integer validated algebra together with `sqrt` when `r=+/-1/2` or the
identity `x^r = exp(r log(x))` otherwise.  See `POWER_FUNCTIONS.md`.


## `0.14.0.dev3` extension

The same generic Taylor-composition framework now also supports `erf`, the
standard-normal PDF `phi`, and the standard-normal CDF `Phi`.  Their coefficient
recurrences and trusted scalar kernels are documented in `SPECIAL_FUNCTIONS.md`.

## `1.0.4.dev6` additional common functions

AutoIA also recognizes ordinary NumPy forms `np.tanh`, `np.sinh`, `np.arctan`
(`np.atan` alias), `np.abs`/`np.absolute`, `np.log1p`, and `np.cosh`.  The
corresponding standard-library `math.sinh`, `math.cosh`, `math.tanh`,
`math.atan`, and `math.log1p` forms are supported through the same local
dispatch mechanism.

The trusted interval layer uses mathematical semantics rather than assuming the
platform libm result is correctly rounded.  `sinh` and `cosh` are built from the
trusted exponential; `tanh` uses a non-overflowing formula based on `exp(-|x|)`;
`arctan` uses rigorous argument transformations plus a bounded power series;
`log1p` reduces rigorously to `log(1+x)` and requires `x > -1`; and `abs` uses
its exact piecewise interval image.

For structured polynomial execution, `abs` preserves the original dependency
when the sign is proved fixed and falls back to the rigorous nonsmooth image
only when zero is crossed.  The sign proof may use the independently propagated
natural interval over the physical input box, so a slightly wider structural
polynomial range cannot spuriously turn a sign-definite `abs(x)` into a
zero-crossing case.  `tanh` and `arctan` deliberately use their rigorous monotone
interval images on broad boxes in Version 1 rather than returning a Taylor
certificate that can be much wider.
